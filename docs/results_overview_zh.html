Inference-Native Memory State：用 LLM 隐状态做长期记忆检索

这份报告整理最终技术叙事：LongMemEval 用来证明 late-layer suffix-final hidden state 可以做 evidence retrieval；PrefEval 用同一思路重选 prompt family，得到最终 companion-memory 配置 2-3-1 + 2-5_token + 2-8_emoji。

核心结论

隐状态可以作为长期记忆检索向量，但有效方案不是“任意层 hidden state + cosine”。 关键是 retrieval suffix 末端的 late layer、去掉共同方向的几何处理、以及与 memory domain 匹配的 prompt view。

LongMemEval：方法验证

Qwen3.5-9B-MLX-4bit 的 K3 hidden-state retriever 加 BM25 top20 rerank：

R@5 = 0.777 · NDCG@5 = 0.822

这是 embedding-baseline scale 的可行性证据，不是 held-out 胜利声明。

PrefEval：最终 companion 配置

最终 K3 是 recall keyword、association token、emotion emoji 三个视角。

R@1 = 0.122 · R@3 = 0.265 · R@5 = 0.332

相对 BM25 和 4bit embedding baseline 有清楚提升，同时保留情绪轴。

为什么做这个项目

目标不是证明 hidden state 永远强于 embedding model，而是验证一个系统假设： 负责读 memory、理解用户、执行后续推理的同一个 LLM，能不能也提供 memory key。 如果可以，memory representation 就不必完全依赖一个外部 embedding stack。

模型原生表示

query 和 memory page 都通过同一个 4bit LLM、同一套 tokenizer 和 prompt 进入表示空间。

Training-free

报告里的主配置没有做 contrastive retriever training；改的是 prompt、层、几何处理和 score fusion。

Embedding model 仍然有价值，尤其是作为 score-level rerank signal。但在最终叙事里， embedding 是辅助分数，不是把 memory representation 交回给外部模型。

关键术语

术语定义
suffix-final在 retrieval suffix 的最后一个 token 位置取 hidden state；此时模型刚被要求把页面或 query 压缩成一个检索 key。
anti_pca_both_k15对 query 和 candidate 两边都去掉前 15 个共享主方向，减少 prompt/corpus common direction。
vector_average_component_normK 个 prompt 分量先做 component normalization，再平均，避免某个 prompt 只因尺度更大而主导。
z-score fusion每个 query 内把不同分数源标准化后加权融合。
oracle union用 label 观察多个 prompt 的 hit union，只用于诊断互补性，不是可部署 scorer。
source_ge3source-count agreement filter；可以看 tuning ceiling，但不进最终默认。

使用的模型

隐状态提取使用 models/Qwen3.5-9B-MLX-4bit。PrefEval 最终配置里的外部 embedding 分数来自 models/Qwen3-Embedding-0.6B-4bit-DWQ。LongMemEval 的本地 embedding baseline 包括 Qwen3-Embedding-8B-4bit-DWQ。

所有上述模型都是本地 4bit 模型。Embedding 在最终系统里是 score-level rerank source， 不是把 embedding vector 拼进 9B hidden vector。

PrefEval prompt sweep：试了什么，什么没用

PrefEval 共测试 25 个 prompt variants。它们覆盖 object（topic/keyword/association/user/emotion/interaction）、 verb（代表/标记/概括）、output form（word/token/emoji）、language（CN/EN/RU/JA）、 以及是否保留“上面”。这里不逐个列出，而是列几个最能解释设计选择的失败或非最终例子。

Emoji 的发现不是“emoji 全都更好”。准确说法是：generic emoji prompt 暴露出一个有用但不稳定的 affect/style signal；最终配置选择 2-8_emoji，因为它明确要求对话情绪。

Prompt 之间的重合度怎么判断

Prompt selection 不只看单 prompt 排名。我们用 oracle union hit@k 和 pairwise Jaccard@k 看 prompt 是否互补。Oracle union 用到了 label，因此只能用于生成假设，不能当无偏结果。

为什么最终 K3 不是 benchmark maxxing

如果只追 PrefEval retrieval 指标，topic control 的 R@5 更高；如果追最尖的表格行， source-screened rows 也可能更高。但最终配置保留 emotion anchor，是为了 companion memory， 不是只最大化这个 benchmark 的 R@5。

Shortlist policy

Source-count shortlist 不进入最终默认配置，因为它把 candidate selection 也变成可调超参。 BM25 scope 是另一个问题：PrefEval 最终用 full-corpus z-score fusion；LongMemEval 使用 vector top20 内 BM25 rerank。两个 benchmark 的 lexical signal 作用不同。

Embedding 的角色

PrefEval 中的 Qwen3-Embedding-0.6B-4bit-DWQ 权重是 0.30。 它主要改善 early rank / MRR，是正交 rerank signal；它不是替代 hidden-state K3。

部署代价

Qwen3.5-9B 的 hidden size 是 4096。按 bf16 存储，一个 prompt view 约 4096 * 2 bytes = 8 KB/page。因此 K3 是 24 KB/page； 20k memory pages 约 500 MB，不含 metadata 和 index overhead。

这个量级对本地 companion memory 是可接受的，尤其是主 representation 不需要额外训练出来的检索模型状态。

PrefEval final K3 回放到 LongMemEval

最终 PrefEval K3 也被 replay 到 LongMemEval-S/round 上。结果说明它有跨 benchmark 迁移性， 但仍低于 LongMem-specific K3。

经验总结

有效

  • late suffix-final hidden state。
  • anti-PCA / centering 去掉共同方向。
  • 多 prompt views，但 prompt 必须贴合 memory domain。
  • PrefEval 上用 component-normalized vector average。
  • BM25 和 4bit Qwen embedding 作为 score-level rerank signal。

无效或风险高

  • final post-norm cosine。
  • 早中层 hidden vectors。
  • sequence mean/max pooling。
  • direct-token wording 作为通用修复。
  • 去掉“上面”作为通用 prompt 改进。
  • Russian explicit prompt。
  • source-count screening 作为最终默认。

局限

  • LongMemEval 主结果只有 94 个 scored questions；一个问题约 1.1 个百分点。
  • prompt 和 fusion 都是在已探索 benchmark subset 上调出来的。
  • PrefEval holdout300 是探索后 sanity check，不是 blind validation。
  • 几何结论绑定 Qwen3.5-9B-MLX-4bit；换模型、量化或 prompt template 后需要复测。
  • PrefEval 最终配置仍使用外部 4bit embedding score，因为它改善 early-rank quality。
